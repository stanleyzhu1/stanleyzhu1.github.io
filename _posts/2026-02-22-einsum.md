I was staring at a transformer attention diagram and got stuck on a tensor contraction: how does **BTD × DNH** become **BTNH**? Pulling at that thread led me to einsum, which turned out to be the cleanest way to think about the whole thing. Two-step chain.

## How does BTD × DNH become BTNH?

Using the legend from the diagram:

- **B**: batch size
- **T**: sequence length (tokens)
- **D**: embedding dimension ($d_{\text{model}}$)
- **N**: number of attention heads
- **H**: per-head dimension

In a standard matmul (`np.matmul`, `torch.matmul`, JAX `@`), the operation only happens between the **last two dimensions** of the inputs. Anything earlier is treated as a batch dimension and broadcast.

For the query projection $Q = X W_Q$:

- Input $X$: shape $(B, T, D)$.
- Weight $W_Q$: shape $(D, N \cdot H)$ — the diagram fuses $N H$ into one dimension for the matmul.

The matmul reduces the inner $D$:

$$(B, T, \mathbf{D}) \times (\mathbf{D}, NH) \rightarrow (B, T, NH)$$

So the multiplication itself produces $(B, T, NH)$. The diagram shows $(B, T, N, H)$ — that's just a **reshape**. The two views hold the same bytes; the 4-D form is convenient because each head $N$ ends up with its own contiguous vector of size $H$, which is what you want for the per-head attention computation that follows.

The "BTD × DNH → BTNH" arrow is doing two things at once: a real reduction over $D$, and a free reshape splitting $NH$ back into $N$ and $H$. The ambiguity was what threw me — once you separate them, the dimensions check out.

In code, the whole thing is one einsum:

```python
# b: batch, t: tokens, d: embedding, n: heads, h: head_dim
Q = einsum('btd,dnh->btnh', X, W_q)
```

Which is a clean lead-in to —

## Teach me einsum

`einsum` (Einstein summation) is often the "final boss" of NumPy/PyTorch/JAX: a single string of indices that can express almost any tensor operation — sums, products, transposes, contractions — without ever calling `transpose` or `reshape` explicitly.

The trick is that it forces you to think about *dimensions*, not function names.

### The core rule

> Indices that appear in the inputs but not in the output are summed over.

A typical call:

```python
np.einsum('ij,jk->ik', A, B)
```

- `ij` labels the axes of $A$.
- `jk` labels the axes of $B$.
- `->ik` says the output has axes $i$ and $k$.
- `j` appears in the input but not the output, so it is summed. That's matrix multiplication.

### Common operations as einsum

| Operation | Notation | What's happening |
| --- | --- | --- |
| Sum | `'i->'` | Sum all elements of a 1-D vector |
| Dot product | `'i,i->'` | Multiply pointwise, sum |
| Outer product | `'i,j->ij'` | Every $a_i$ times every $b_j$ |
| Trace | `'ii->'` | Sum of diagonal |
| Transpose | `'ij->ji'` | Swap axes |
| Matrix-vector | `'ij,j->i'` | Row-column multiply |
| Batched matmul | `'bij,bjk->bik'` | Matmul across batch $b$ |

### A three-step algorithm for writing one

When you're looking at a complex tensor operation:

1. **Label every input axis** with a letter ($b$ for batch, $h$ for heads, $i$/$j$ for rows/cols, etc.).
2. **Pick the survivors** — which axes you want in the output.
3. **Write the string**: `'input1_indices,input2_indices->output_indices'`. Anything in the inputs but missing from the output gets summed.

### Worked example: attention scores

To compute query-key scores in multi-head attention you have:

- $Q$ shape `(batch, heads, seq_q, dim)` → `bhqd`
- $K$ shape `(batch, heads, seq_k, dim)` → `bhkd`
- Goal: scores of shape `(batch, heads, seq_q, seq_k)` → `bhqk`

```python
scores = np.einsum('bhqd,bhkd->bhqk', Q, K)
```

`d` is omitted from the output, so it's contracted — exactly the per-head dot product over the embedding dimension. No transposes, no reshapes.

### Why bother

- **Fewer intermediate copies.** Writing `transpose → reshape → matmul → reshape` allocates temporaries; one einsum can fuse the whole pattern.
- **Reads better once you speak indices.** `'bhqd,bhkd->bhqk'` is more legible than `(Q @ K.transpose(-1, -2))` once shapes get past 3 dimensions.
- **Framework-agnostic.** The same string works in NumPy, PyTorch, JAX, TensorFlow.

Going back to the original puzzle: `'btd,dnh->btnh'` is the contraction *and* the implicit head-split, said in one breath. That's what the diagram was actually doing.
